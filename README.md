# METRO Team Board

METRO 팀원이 구글 폼으로 낸 **작업 가능 시간 · 휴가·일정**을 디렉터가 한눈에 보는 팀 일정 대시보드예요.
근태 관리 사이트가 아니라서 화면에는 ‘근무·출근·결근’ 같은 말을 쓰지 않아요.

```
구글 폼 제출 → 관리자 시트(출근판_관리자시트) → 이 사이트(GitHub Pages) → 디렉터 확인
                                   ↑
                    회의 확정만 Apps Script로 '회의 확정' 탭에 저장
```

---

## 1. 기존 프로젝트 분석

| 항목 | 기존 상태 |
|---|---|
| 파일 | `index.html` 한 파일(1,253줄)에 HTML·CSS·JS가 모두 들어 있음 |
| 데이터 연결 | 관리자 시트의 탭을 ‘웹에 게시’한 CSV 3개(명단·근무시간 응답·휴가일정 응답)를 브라우저에서 직접 읽음. 서버 없음 |
| 확인한 범위 | GitHub 공개 페이지로 약 1,000줄까지 읽음. 나머지(월간 그리기·초기화 약 250줄)는 공개 페이지로 읽을 수 없어 새로 작성 |
| 주의할 점 | 이전 작업에서 ‘빠진 멤버’로 연결했던 `gid=1701192026`은 실제로는 **‘스케줄 현황’ 탭**이었음 → 이번에 바로잡음 |

## 2. 유지 · 수정 · 제거

**그대로 유지한 것**
- 시트 연결 방식과 주소(같은 게시 CSV), 폼 링크 두 개
- 같은 사람이 여러 번 내면 **가장 최근 응답만** 사용
- 휴가·일정 **취소 규칙**: 같은 사람·같은 시작일로 나중에 ‘취소’를 내면 앞선 일정이 지워짐
- ‘종류’ 판별: `다른 시간`/`일해요` → 그날만 다른 시간, `몇 시간`/`빠져` → 일부 시간 빠짐, 그 밖 → 종일
- 시간 읽기: `10-16`, `10시-16시`, `13:30-18`, `10-12, 14-18`, `22-02`(익일 02시), `가능`(시간 미정)
- `(예시)`로 시작하는 줄 무시

**바꾼 것**
- 한 파일 → 역할별 파일(설정 / 공통 도구 / 데이터 판단 / 화면 / 시작)
- 상태 판단을 **함수 하나(`resolveStatus`)**로 모아 모든 화면이 같이 씀
- ‘스케줄 현황’ 탭은 읽지 않고, 명단 + 응답에서 직접 계산 (아래 5-4 참고)
- ‘빠진 멤버’ 탭을 연결해 현재 팀원 수와 미제출 계산에서 제외
- 회의 확정을 브라우저 저장 → **시트 ‘회의 확정’ 탭 저장**(Apps Script)
- 시트 글자를 HTML로 넣던 방식 → 모두 글자로만 넣음(XSS 차단)

**없앤 것**
- ‘출근·근무’ 표현, 행 전체를 강한 색으로 칠하는 표시, 사람마다 큰 카드, 모바일에서 표를 줄여 보여주는 방식

## 3. 정보 구조

메뉴는 PC·모바일 모두 **오늘 · 주간 · 월간 · 회의 · 팀 명단** 다섯 개예요. 주소에 화면 이름이 없으면 항상 ‘오늘’로 열려요.

| 화면 | 보여주는 것 | 보여주지 않는 것 |
|---|---|---|
| 오늘 | 요약 5칸, 오늘 작업 가능(시간순), 오늘 휴가·일정, 별도 확인 3그룹, 오늘 확정 회의 | 다른 날짜 |
| 주간 | 날짜별 작업 가능·휴가·일정별 확인, 장기 OFF·미제출 한 번만, 이 주 회의 후보 3개(참고) | 장기 OFF 매일 반복 |
| 월간 | 휴가·기간 일정, 확정 회의 (달력엔 점·인원 수·깃발만) | 작업 가능 시간 |
| 회의 | 조건 → 후보 3~5개 비교 → 확정 → 확정 목록(완료·취소) | 설문 제작 기능 |
| 팀 명단 | 상태 요약 6칸, 필터·검색, 압축 목록, 폼 링크, 이전 참여자 | 큰 프로필 카드 |

모바일(1023px 이하)은 **아래 고정 메뉴**, PC(1024px 이상)는 **왼쪽 메뉴**예요. 머리글에는 이름 · 날짜 · 마지막 갱신 시각 · 새로고침만 있어요.

## 5. 상태 판단 로직

모든 판단은 `js/data.js` 한 곳에 있고, 화면 파일은 그 결과를 보여주기만 해요.

### 5-1. 사람 상태 — `resolveStatus()` (우선순위 순서)

| 순위 | 조건 | 상태 | 비고 |
|---|---|---|---|
| 1 | ‘빠진 멤버’ 탭에 이름이 있음 | 제외 | 명단·인원 수·미제출 어디에도 안 셈. ‘이전 참여자 보기’에서만 |
| 2 | 명단 `활동 상태`에 ‘장기’ | **장기 OFF** | 폼을 냈어도 장기 OFF. 미제출에서 제외 |
| 3 | 명단 `일정 확인 방식`에 ‘일정별’ | **일정별 확인 필요** | 폼을 냈어도 이 상태. 미제출에서 제외 |
| 4 | 작업 가능 시간 응답이 있음 | 가능 시간 등록 | |
| 5 | 그 외 | **스케줄 미제출** | |

`제한적 활동`은 상태가 아니라 표시용 꼬리표예요. 판단은 위 표대로 하고, 화면에 ‘제한적 활동’을 함께 보여줘요.

### 5-2. 어떤 날 작업 가능한지 — `availability(사람, 날짜)`

| 그날 상황 | 결과 |
|---|---|
| 장기 OFF | 계산에서 빠짐 |
| 종일 휴가·일정 | 작업 가능 아님 → ‘휴가·일정’에 표시 |
| ‘그날만 다른 시간’ 제출 | 그 시간으로 대체 (`그날만 변경`) |
| ‘몇 시간 빠짐’ 제출 | 평소 시간에서 그 시간만 빼기 (`일부 빠짐`) — 휴가·일정에도 같이 표시 |
| 평소(요일별) 시간 | 그대로 |
| 일정별 확인 필요 / 미제출인데 그날만 따로 ‘다른 시간’을 냄 | 그날은 작업 가능으로 봄 (`개별 등록`) |

### 5-3. 회의 후보 — `meetingCandidates()`

대상 팀의 현재 팀원 중 **장기 OFF를 뺀 사람**을 30분 간격으로 검사해 한 사람씩 나눠요.

| 분류 | 뜻 |
|---|---|
| 자동 확인 가능 | 작업 가능 시간이 회의 시간 전체를 덮음 |
| 추가 확인 필요 | 일정별 확인 필요 · 스케줄 미제출 · 시간 미정 → **불가로 처리하지 않음** |
| 참여 어려움 | 그 시간에 휴가·일정이 있거나, 등록 시간이 회의 시간과 안 맞음 |

순위: ① 자동 확인 인원 많은 순 → ② 휴가·일정 충돌 적은 순 → ③ 추가 확인 적은 순 → ④ 이른 날짜·시간.
비슷한 후보가 겹치지 않게 같은 날은 2시간 이상 떨어진 것만, 하루 최대 2개까지 보여줘요.

### 5-4. ‘스케줄 현황’ 탭을 읽지 않는 이유

‘스케줄 현황’은 세 그룹의 이름만 담고 있어서, 날짜별 계산·회의 후보·팀 명단 필터에 필요한 정보를 얻으려면 어차피 명단과 응답을 다시 읽어야 해요. 두 곳에서 따로 계산하면 게시 지연(최대 몇 분) 때문에 숫자가 어긋날 수 있어서, **명단 + 근무시간 응답 + 빠진 멤버에서 한 번만 계산**하는 쪽을 기준으로 정했어요. 시트의 ‘스케줄 현황’ 탭은 관리용으로 그대로 두면 되고, 두 결과는 같은 규칙이라 일치해야 해요.

## 6. 파일

| 파일 | 역할 |
|---|---|
| `index.html` | 화면 뼈대, 아이콘, 메뉴 |
| `config.js` | **설정은 여기만.** 시트 주소, 폼 주소, Apps Script 주소, 헤더 이름, 새로고침 주기, 회의 기본값, 팀 색 |
| `css/style.css` | 디자인 (모바일 먼저, 1024px부터 왼쪽 메뉴, 다크 모드 대응) |
| `js/core.js` | 공통 도구: 한국 시간 날짜·시간 계산, CSV 읽기, 헤더 이름으로 열 찾기, 안전한 화면 요소 만들기, 팀 색, 상태 이름 |
| `js/data.js` | 시트 불러오기, **상태 판단**, 날짜별 계산, 회의 후보, 회의 저장소 |
| `js/views.js` | 다섯 화면 그리기 |
| `js/app.js` | 화면 전환, 불러오기·오류·빈 상태, 자동 새로고침 |
| `apps-script/Code.gs` | 회의 확정 저장용 Apps Script (시트에 붙여 넣는 코드. 사이트에는 쓰이지 않음) |

## 7. 반응형 확인 결과

헤드리스 Chrome으로 360 · 390 · 430 · 768 · 1280px에서 다섯 화면을 모두 열어 자동 점검했어요(25개 조합 모두 통과).

- 가로 스크롤 없음
- 모든 글자 14px 이상
- 모바일 버튼·탭 높이 44px 이상
- 하단 메뉴 5개 겹침·글자 잘림 없음
- 맨 아래 내용이 하단 메뉴에 가리지 않음
- 긴 이름(‘알렉산드라 김민서’)·긴 메모는 잘리지 않고 줄바꿈
- 월간 달력 한 칸 47×63px(390px) · 42×63px(360px), 날짜 글자 15px
- 기기 시간대를 미국·영국으로 바꿔도 한국 날짜로 표시

## 8. 오류 · 빈 데이터 테스트 결과

| 상황 | 화면 |
|---|---|
| 명단 시트 불러오기 실패 | 원인(HTTP 코드)과 확인할 곳 안내 + ‘다시 시도’ |
| 시트가 ‘웹에 게시’되지 않음(웹페이지가 옴) | ‘웹에 게시에서 CSV로 게시했는지’ 안내 |
| 시트에 헤더만 있음 | 모든 화면에서 0명 요약과 “~이 없어요” 안내 |
| 빠진 멤버 탭만 실패 | 나머지는 정상, 팀 명단 하단에 안내 |
| 보는 중에 새로고침 실패 | 이전 데이터를 유지하고 위쪽에 “○시 기준으로 보여주는 중” + ‘다시 시도’ |
| 회의 API(Apps Script) 장애 | 확정 목록에만 오류 안내, 후보 계산은 정상 |
| Apps Script 미연결 | “이 기기에만 저장 중” 안내, 확정한 회의에 ‘이 기기’ 표시 |
| config.js에 명단 주소 없음 | 설정 방법 안내 |
| 시트에 `<img onerror=…>` 같은 글자 | 실행되지 않고 글자 그대로 표시 |
| 확정할 때 비밀번호 틀림 | 적어둔 회의명·메모는 그대로 두고 오류 문구만 표시 |

## 9. 배포 방법

### 9-1. ‘빠진 멤버’ 탭 게시 (처음 한 번)
1. 관리자 시트 → **파일 > 공유 > 웹에 게시**
2. 링크 탭에서 **‘빠진 멤버’** 탭과 **‘쉼표로 구분된 값(.csv)’**을 고르고 게시
3. 나온 주소를 `config.js`의 `departed: ""` 따옴표 안에 붙여 넣기

빠진 멤버 탭은 `이름` 헤더만 있으면 돼요. `팀`, `나간 날짜`, `메모`가 있으면 ‘이전 참여자 보기’에 함께 보여줘요.

### 9-2. 사이트 파일 올리기
1. GitHub 레포 `METRO_team-board` → **Add file > Upload files**
2. 받은 폴더 안의 `index.html`, `config.js`, `README.md`와 `css`, `js`, `apps-script` 폴더를 통째로 끌어다 놓기 (기존 `index.html`은 덮어써짐)
3. **Commit changes**
4. 1~2분 뒤 사이트를 열고, 예전 화면이 보이면 강력 새로고침(PC: Ctrl+Shift+R / 모바일: 탭 닫았다 다시 열기)

GitHub Pages 설정은 바꿀 필요 없어요(기존처럼 main 브랜치 / 루트).

### 9-3. Apps Script 연결 (회의 확정을 팀 전체와 공유)
1. 관리자 시트 → **확장 프로그램 > Apps Script**
2. `Code.gs`의 기본 내용을 지우고 `apps-script/Code.gs` 내용을 붙여 넣은 뒤 저장
3. 왼쪽 **⚙ 프로젝트 설정 > 스크립트 속성 > 스크립트 속성 추가**
   속성: `ADMIN_PASS` / 값: 디렉터만 아는 비밀번호
4. (선택) 편집기 위쪽 함수 목록에서 `setup`을 고르고 **실행** → 권한 허용 → 시트에 ‘회의 확정’ 탭이 생겨요
5. **배포 > 새 배포 > 유형: 웹 앱**
   실행 계정: **나** / 액세스 권한: **모든 사용자** → 배포
6. 나온 **웹 앱 URL**(`…/exec`로 끝남)을 `config.js`의 `meetingApi: ""`에 붙여 넣고 커밋
7. 사이트 → 회의 → 후보에서 ‘이 시간으로 확정’ → 비밀번호 입력 → 시트 ‘회의 확정’ 탭에 한 줄 생기면 완료

`Code.gs`를 나중에 고치면 **배포 > 배포 관리 > ✎ > 버전: 새 버전 > 배포**로 올려요(URL은 그대로).

**권한에 대해:** ‘모든 사용자’는 로그인 없이 부를 수 있다는 뜻이에요. 회의 목록 읽기는 누구나 되고(사이트가 보여줘야 하니까), 저장·상태 변경은 비밀번호가 있어야 돼요. 비밀번호를 10분 안에 20번 틀리면 잠깐 잠겨요. 이 스크립트는 ‘회의 확정’ 탭만 읽고 쓰고, 폼 응답 탭은 건드리지 않아요.

### 9-4. 배포 후 확인
- [ ] 첫 화면이 ‘오늘’이고 인원 수가 시트와 맞음
- [ ] Mika·동동은 ‘일정별 확인 필요’, 석중은 ‘장기 OFF’, 미제출 명단이 시트 ‘스케줄 현황’과 같음
- [ ] 빠진 멤버가 팀 명단에 안 보이고 ‘이전 참여자 보기’에만 있음
- [ ] 회의 하나를 확정하면 시트 ‘회의 확정’ 탭에 저장되고, 다른 기기에서도 보임

## 10. 설정 바꾸기 (`config.js`)

- **시트 헤더 이름을 바꿨다면** `headers`의 해당 이름만 고치면 돼요. 열 순서는 바꿔도 괜찮아요.
- **팀 색을 직접 정하려면** `teamColors: { "아트팀": "#B0587A" }`처럼 적어요. 안 적으면 팀 이름 순서대로 차분한 색이 붙어요.
- **새로고침 주기**는 `refreshMinutes`, **회의 기본값**(이름·길이·시간 범위·기간)은 `meetingDefaults`.

## 11. 알아둘 점

- 구글 ‘웹에 게시’ CSV는 구글 쪽에서 몇 분 늦게 갱신될 수 있어요. 폼을 낸 직후 바로 안 보이면 잠시 뒤 새로고침하세요. (회의 확정은 Apps Script로 바로 읽어서 즉시 보여요.)
- 회의 후보는 폼 응답 기준 **추정**이에요. ‘추가 확인 필요’ 인원은 직접 물어봐 주세요.
- 이 사이트와 게시된 CSV는 주소를 아는 사람은 누구나 볼 수 있어요(기존과 같음).
- 개발 환경에서는 실제 시트에 접속할 수 없어서, 실제 시트와 **같은 헤더·같은 값 형식**의 테스트 데이터로 검증했어요. 배포 후 9-4 체크리스트로 한 번 확인해 주세요.
